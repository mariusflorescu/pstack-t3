### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`. Build the activity file from T3. Page through `t3_thread_list` for the project with `includeSubagents: true`, then call `t3_thread_read` on each thread with `limit: 1` and `runLimit: 1`. For each thread with a `thread.worktreePath`, write the line `<worktreePath>\t<timestamp>\t<threadId>`, where the timestamp is the latest run's `startedAt`, else its `requestedAt`, else `thread.updatedAt`, so a thread with no started run still counts as recent activity. Then run `scripts/worktree-audit.sh --activity <tsv> [-b <pr-base-ref>] [repo-path]` (principle-build-the-lever). Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at `~/.t3/worktrees/myrepo/x` (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, PR state, and the newest thread that touched it, then suggests a bucket.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from the user or sidebar and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan `delegate_task` children out to read the threads with `t3_thread_read` and report whether the chat is pinned or ongoing and which worktrees it touches (principle-guard-the-context-window, thread timelines are bulk). A pinned chat spawns arena and repro trees into sibling worktrees via `delegate_task` isolation worktrees or `t3_thread_launch` threads, and those are in use even when their names never hit the sidebar. Pick each subagent's reasoning level and fast or standard speed for the job, per the Subagents section.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` is untracked throwaway, safe to drop, but name the files. Per Autonomy, clean and merged and not-in-use proceeds. `wip` and in-use pause.
5. Prune the confirmed set. Per path, `git worktree remove --force <path>`. If the dir survives on ignored build artifacts, `rm -rf` it, then `git worktree prune`. Branch refs survive, so no commits are lost. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
